# Тестовый план СМП

## Область тестирования и подход

Проверяется работа СМП через API. Для Authorization и Card Management используются классы эквивалентности, граничные значения и pairwise. Для Gateway, Switch, Terminal Simulator, Transaction Logger и Web Dashboard используются smoke тестирование и критический путь.

## Критерии входа

- Сервисы запущены, health-check и API доступны.
- Подготовлены карты с нужными статусами, балансом и лимитами.

## Критерии выхода

- Выполнены тест-кейсы и чек-листы.
- Нет открытых критичных и высоких проблем в основном платёжном сценарии.

## Критерии приостановки

Тестирование приостанавливается, если не работает Authorization или Card Management, нет тестовых карт или API возвращает техническую ошибку.

## Критерии возобновления

Тестирование продолжается после восстановления сервисов, повторной проверки health-check и подготовки данных.

## Ресурсы

- **Тестовая среда:** сервисы СМП, запущенные в Docker, и тестовая база данных.
- **Тестовые данные:** карты с разными статусами, лимитами и балансом.

## Расписание

1. Подготовить тестовую среду и данные.
2. Подготовить test-design и pairwise-наборы для сервисов ядра.
3. Выполнить проверки API и взаимодействий сервисов.
4. Пройти дымовой чек-лист и критический путь.
5. Сверить результат с критериями выхода.

## Риски

- Недоступность Card Management мешает проверить Authorization полностью.
- После успешной авторизации меняется баланс тестовой карты.

## Метрики

Количество выполненных тест-кейсов, пройденных пунктов чек-листа, открытых проблем, покрытых классов, границ и строк pairwise-набора.
